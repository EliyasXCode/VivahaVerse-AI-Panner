🏛️ Section 1: Full-Stack MERN Architecture
Q1: Can you give an architectural overview of your VivahaVerse AI project?
VivahaVerse AI is a production-grade MERN platform for luxury Indian destination wedding planning. It comprises: 1. Frontend Layer: React 18, Vite, Tailwind CSS, Framer Motion, Context API. 2. Backend Layer: Node.js & Express API with Helmet, CORS, Rate Limiter, Cookie Parser, and JWT Auth. 3. Database & AI Layer: MongoDB Atlas storing destination metrics, integrated with @google/genai using gemini-3.7-flash and gemini-3.1-flash-image.
💣 Interviewer Counter-Question: "Why decouple AI reasoning from the database instead of letting Gemini query the web?"
Allowing LLMs to search the web leads to pricing hallucinations. We implemented a Database-Grounded RAG Architecture: Express queries MongoDB for real, verified destination tariffs and room rates first, then feeds this grounded context to Gemini.
Q2: How do you handle State Management across React components?
We use React Context API split into domain contexts: AuthContext (User login session & checklist state) and SavedContext (Favorites, saved plans, and venue compare matrix). This prevents unnecessary prop drilling while keeping state scoped.
🧠 Section 2: Generative AI & Prompt Engineering
Q3: How do you ensure Google Gemini returns strict JSON instead of conversational text?
We pass responseMimeType: 'application/json' in the Gemini model config object. Additionally, our backend Node.js service uses a regex sanitizer to strip accidental markdown backticks before calling JSON.parse().
💣 Interviewer Counter-Question: "What happens if Gemini API key fails or experiences high demand (HTTP 503)?"
The application is fault-tolerant. We designed a fallback service layer: if the Gemini API throws a quota or rate-limit error, our backend intercepts it, extracts top matching records from MongoDB, and serves pre-curated responses and photography fallbacks without crashing the UI.
Q4: How does the AI Wedding Visualizer image engine work?
The visualizer converts user inputs (Destination, Ceremony style, Lighting, Palette) into a luxury editorial photography prompt and calls gemini-3.1-flash-image via @google/genai. The base64 or inline image URL is returned to the client alongside an AI concept visualization disclaimer.
💰 Section 3: Financial Engine & Database Design
Q5: Is the Budget Calculator calculated by AI or mathematically?
It is a hybrid deterministic engine. Math calculation must never be left purely to an LLM. 1. Deterministic Math: budget.service.js calculates exact costs for venue daily tariffs, room nights, plate cost × guests × functions, decor, media, planner fee (10%), GST taxes (18%), and contingency (5%). 2. AI Optimization: Calculated numeric tiers are passed to Gemini to generate actionable cost-saving tips.
Q6: How are database schemas indexed in MongoDB for fast destination searching?
In Destination.js, we created compound indexes on slug, state, region, budgetRange.min, budgetRange.max, and text search indexes on name, state, description. This accelerates multi-filtering queries.
🔒 Section 4: Authentication & Security
Q7: Why store JWT tokens in HttpOnly cookies instead of localStorage?
localStorage is vulnerable to Cross-Site Scripting (XSS) attacks where malicious scripts can read tokens. HttpOnly cookies cannot be accessed via client JavaScript (document.cookie), ensuring protection against token theft.
